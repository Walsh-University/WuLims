# Styling (SCSS + Bootstrap)

WuLims uses Bootstrap as a base and layers a custom SCSS theme on top. The SCSS source is the single source of truth.

Think of styling in WuLims like this:

> SCSS is the source code.
>
> CSS is the compiled output.

You edit the source (SCSS).

The browser reads the output (CSS).

Just like Python → bytecode or C → binaries, you don’t edit the generated file.

## Rules (Read First)

- Do **not** add inline styles or `<style>` blocks in HTML templates.
- Do **not** edit compiled CSS in `static/css/` by hand.
- Do not add \<style\> blocks to templates
- All project styling is self-contained under `/assets`.
- Use SCSS for custom styling; the compiled CSS is generated by SASS.

## Background: What Is SCSS? (Just Enough to Be Dangerous)

Sassy Cascading Style Sheets.  :shrug:

It's the modern, enterprise way to write CSS and style web apps.

- https://sass-lang.com
- https://www.upwork.com/resources/what-is-scss
-
SCSS is a superset of CSS. Everything valid in CSS is valid SCSS — plus a few handy features.

You are not expected to write SCSS unless you want to explore it.

Variables (reusable values)

```scss
$walsh-maroon: #6d0120;
$primary: $walsh-maroon;
```
Instead of repeating colors everywhere, we define them once.

Nesting (clearer structure)
```scss
.sidebar {
    border-right: 1px solid rgba(0, 0, 0, 0.08);

    .nav-link.active {
    font-weight: 600;
    }
}
```
This compiles to normal CSS — it’s just easier to read and organize.

Partials (files that get included)

- Files starting with _ are partials
- They do not produce CSS on their own
- They are included by wulims.scss

Think of them like helper modules.


## Where Styles Live

**SCSS source** (this is what developers edit)
```
assets/
└── scss/
    ├── _variables.scss   # Theme tokens + Bootstrap variable overrides
    ├── _overrides.scss   # Component tweaks and custom utilities
    └── wulims.scss       # Entry point that imports Bootstrap + overrides
```
**Generated CSS** (this is what the browser loads)
```
static/
└── css/
    └── bootstrap.wulims.min.css  # Generated output (do not edit)
```
The CSS is linked in the base template so every WuLims page gets it:

```html
<link rel="stylesheet" href="{% static 'css/bootstrap.wulims.min.css' %}">
```

Only one CSS file is served to the browser (saves bandwidth).

Everything else exists to generate that file.

## How the Theme Works

When the CSS is built:

Theme variables are loaded first
- this is where we define WuLims colors, fonts, and Bootstrap defaults

Bootstrap’s source styles are loaded next
- Bootstrap reads our values and adapts itself

Overrides and custom utilities are applied last
- small refinements specific to WuLims

This gives us a clean separation:

_variables.scss
- "What does WuLims look like?"

_overrides.scss
- "Tweak this specific component or behavior"

1. `wulims.scss` imports `_variables.scss` first, so Bootstrap is configured with your theme values.
2. Bootstrap’s source SCSS is imported next.
3. `_overrides.scss` is imported last for component tweaks and custom utilities.

This gives you a clean split:
- **Theme tokens** live in `_variables.scss` (colors, typography, component defaults).
- **Custom rules** live in `_overrides.scss` (utility classes, component refinements).

## Making Style Changes (If You Need To)

### Step 1: Decide where the change belongs

#### Colors, fonts, layout defaults
- assets/scss/_variables.scss

#### Component tweaks or utility classes
- assets/scss/_overrides.scss


### Step 2: (Optional) Add a new partial

If styles start to grow, you may add another _something.scss file and import it in wulims.scss.

### Step 3: Rebuild the CSS

The SCSS must be compiled into CSS before the browser sees it.

```bash
make css
```

> Most students will not run this themselves.
>
> The compiled CSS is already included in the repository.

## Installing SASS

Do I Need to Install Anything?

- Most students: no.

You can work on:
- Django views
- Templates
- HTMX
- Models
- Business logic

...without ever touching SCSS.

If you want to rebuild the CSS

The instructor or project maintainer handles this.

We use Sass, a command-line tool that converts SCSS --> CSS.

If you ever need it, there are multiple ways to install it.
You do not need to know what “Ruby gems” are.

The project Makefile already hides the details.

SASS is required to build the CSS from SCSS. If you need to recompile the SCSS to CSS you need to install it with RubyGems:

```bash
gem install sass
```
This step assumes you have Ruby installed first.

## Why We Do It This Way (Important)

This mirrors how real teams work:
- Designers and senior engineers define the theme
- Most developers use existing classes and components
- Generated files are committed, not hand-edited
- Visual consistency is enforced centrally

In WuLims:
- You focus on behavior
- The system takes care of appearance

**If something looks wrong, ask why before changing how.**

That habit alone puts you ahead of most junior developers.
